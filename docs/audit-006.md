# Engineering quality and security audit

Snapshot: 2026-10-05, starting from `master` at `4c002c8`. The recorded findings cover correctness, security, database integrity, testing and maintainability against the [architecture](architecture.md). This records repository evidence and dispositions, not a production certification or proof that all vulnerabilities have been excluded.

Audit severity definitions: Critical means an exploitable/data-loss issue needing immediate action; High a significant correctness/security/integrity problem; Medium a meaningful reliability/maintainability gap; Low a limited-impact improvement. Upstream advisory ratings and demonstrated application impact are distinguished below.

## Findings and disposition

| ID / severity | Evidence and impact | Resolution |
| --- | --- | --- |
| A1 — High | [TicketService](../backend/src/main/java/io/github/panteliszara/issunexa/ticket/TicketService.java) originally relied on login-time session authorities for staff writes. After changing a persisted AGENT/ADMIN role to REQUESTER, real-session requests still changed status (`200`); claims raised an unhandled role exception. Revoked privileges could affect another requester's Ticket. | **Fixed:** both staff mutations check the current persisted role before looking up/mutating the Ticket, retaining method-level security. Four regressions cover both original staff roles, generic `403`, unchanged Ticket/version and unchanged history. |
| A2 — High maintenance priority | At this audit's baseline, the resolved [Maven graph](../backend/pom.xml) included Tomcat 11.0.24 and Jackson core/databind 2.21.5 / 3.1.5. OSV matched ten distinct advisories across five artifacts, including upstream Critical/High ratings. Application exploitability was not established: Tomcat container DIGEST/FORM/constraint authorization and the specified Jackson identity/polymorphic/XML/Path/DataInput usage were absent from application configuration/request DTOs. That did not clear transitive usage or other vendor notices. | **Remediated:** coherent Tomcat 11.0.26 and Jackson 2.21.7 / 3.1.7 maintenance patches. The [remediation record](dependency-security-012.md) preserves each advisory's severity, reachability evidence, vendor findings and residual disposition. The additional vendor Reader name-limit defect has bounded regressions for both generations. |
| A3 — Medium | All three listing controllers accepted individually valid integers whose `page × size` exceeded JPA's signed-int offset limit. PostgreSQL integration requests raised an unhandled `InvalidDataAccessApiUsageException` instead of a client error. | **Fixed:** shared [offset validation](../backend/src/main/java/io/github/panteliszara/issunexa/shared/web/PaginationValidation.java) at each API boundary returns the existing generic `400` Problem Detail. Six regressions cover rejection on all three routes and acceptance at the exact limit with size 1. |
| A4 — Medium | [Compose](../compose.yaml) supplies the same PostgreSQL user to bootstrap and backend JPA/Flyway. On a fresh cluster, the [official image](https://hub.docker.com/_/postgres) creates that user as superuser. Application connections consequently have unnecessary administrative power. Existing-volume privileges were not assumed or changed; no SQL injection was demonstrated. | **Follow-up database privilege separation:** separate runtime/migration/admin privileges with safe existing-data upgrade tests. Changing credential and schema ownership requires its own reviewed configuration work. |
| A5 — Medium | [AuthenticationController](../backend/src/main/java/io/github/panteliszara/issunexa/auth/api/AuthenticationController.java), [SecurityConfiguration](../backend/src/main/java/io/github/panteliszara/issunexa/shared/security/SecurityConfiguration.java) and [Nginx](../frontend/nginx.conf) have no login-attempt budget. A client can obtain its own CSRF session and repeatedly invoke adaptive password verification. Guessing/capacity risk increases with untrusted runtime exposure; no denial of service or credential compromise was reproduced. | **Follow-up login-attempt handling:** define limits, identity/proxy trust and recovery policy before adding enforcement. The current documented runtime has loopback defaults. |
| A6 — Low | [TicketController](../backend/src/main/java/io/github/panteliszara/issunexa/ticket/api/TicketController.java) omitted page/size from scalar binding checks, unlike comments/history. Explicit blank values returned `200` using defaults; repeated/array-shaped parameters lacked the same guard. This made pagination input handling inconsistent. | **Fixed:** extend the existing binder to page/size. Two parameterized regressions exercise blank, repeated and array-shaped values for each parameter. |

No application-level Critical exploit or data-loss defect was confirmed in this audit. This does **not** downgrade or dismiss the upstream Critical advisories recorded in finding A2. Dependency remediation is recorded separately above; the privilege and abuse-control follow-ups remain unresolved. This audit does not authorize public deployment.

## Verification and limitations

- Regression-first PostgreSQL runs reproduced A1/A3 (seven failing/error cases, three passing offset-boundary cases) and A6 (two failing cases). The fixes add twelve regression cases to the existing integration suite.
- Focused backend service/controller/integration checks passed 228 tests before the final scalar-binding adjustment; the subsequent full Maven `verify` passed **511 tests**, zero failures/errors/skips.
- From `frontend/` with Node 24.21.0: `npm ci`, `npm run lint`, `npm run typecheck:e2e`, `npm test` and `npm run build` passed. Vitest passed **342 tests**.
- Real-stack `npm run test:e2e` passed **7/7 tests**: six desktop Chromium journeys and one Pixel 7 Chromium emulation journey. An intentional no-matching-tests run returned exit code 1; both runs removed their own containers, network, volume and project image tags. Unrelated cached images were left untouched.
- The three changed Markdown documents rendered successfully and all **57 local links** resolved. Command references, lockfile provenance and `git diff --check` were verified.
- Dependency queries are snapshots, not vulnerability-free guarantees. OSV scanned 147 Maven artifacts, including test dependencies; upstream data and vendor notices have different coverage. No container OS package scanner, production penetration test, load benchmark or TLS deployment assessment was performed. Compiler warnings from JVM test instrumentation are not application failures.
- Scanner responses, dependency trees, test logs and generated artifacts are excluded from the commit. Existing CI remains the independent validator, and maintainer review is required before merge.
